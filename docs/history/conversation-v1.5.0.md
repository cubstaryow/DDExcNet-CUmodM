### 生成失败才兜底

- 当前实际安装的 CCL 已有同入口生成前缀；HarmonyX 会执行全部前缀，旧 MPfix 因此可能在 CCL 创建 A 后再创建 B，并覆盖返回值，留下两件不同对象。
- `UtilsCreateCompatPatch.cs` 的前缀只记录购买 ID，不再造物、不覆盖成功结果。后缀低优先级执行，正常生成成功时不补发。
- `CraftSpawnScope.cs` 通过原生主机合成入口限定当前非液体结果 ID，嵌套与异常出口恢复作用域。客机、单机、购买、掉落、世界生成与娱乐赠品不进入失败补救。
- 补救只调用一次 CCL 完整生成流程，保留激活、场景迁移和物品初始化；原生空资源异常准确识别，其它构造异常保留。配方数量、材料扣除和失败回滚交给 MP。
- “道生一 一生二”继续独立工作：购买赠送一份，普通物品生成20%赠送一份，递归保护保留，不复制界面对象。关闭合成兜底不会同时关闭娱乐功能。
- 对象级网络登记保留幂等，但不再把“两次实例化”的根因误写成“同一个对象登记两次”。未删除场上疑似重复物品。

## 1. 伤害重算与激进模式

主要文件：

- `src/DDEN.MPfix/BlockDamageSyncFix.cs`
- `src/DDEN.MPfix/BuildingDamageRelax.cs`
- `src/DDEN.MPfix/UnitDamageRepair.cs`
- `src/DDEN.MPfix/AttackReport.cs`
- `src/DDEN.MPfix/FrameWorkQueue.cs`
- `src/DDEN.MPfix/MPfixPlugin.cs`

### 分支开关与基础模式

保留 `SyncBlockBreak`、`SyncBuildingDamage`，新增 `SyncBodyDamage`。三者分别控制方块、BuildingEntity 类目标、Body/Limb 类角色或肢体目标；部分敌对生物走后两类不同路径。

`AggressiveConverge` 默认关闭，只处理主客机均开启修复的对应分支；关闭某分支后，不会被激进总开关绕过。

基础模式修复主机代理客机攻击时漏掉的世界伤害倍率 `attackdamage`。MP 重算使用该客机对应角色在主机上的状态，不是直接拿主机玩家的种族或力量替代。修复沿用这一重算路径，仅补漏乘；它不负责消除角色状态缓存、工具状态或预测同步时序的全部差异。

单位攻击复制 `AttackInfo` 后修改伤害字段，不污染原共享攻击模板，也不将世界伤害倍率额外乘到击退力量上。合法的低于1倍伤害设置也处理。方块保留 MP 原有伤害判定，不恢复已删除的 `BlockDamageRatio` 配置。

### 激进方块上报

- 命中/碎块回调只收集轻量记录，移出逐块即时序列化与发包。
- 每0.35秒攒批，最多64块/批，每帧最多发送一批；可靠发送失败时保留待发送数据。
- 主机接收时按发送者校验，后续 FIFO 分帧结算：每帧最多16块，达到1.5ms预算暂停。
- 保留12格距离、块编号/原伤害记录身份、已有损伤比例等校验；默认已有损伤门槛50%，仅补差值。
- 不直接删块、不扫描地图；破坏、掉落与广播仍走原流程。
- 删除累计3000次后停止上报的旧限制；保留重复坐标去重，并在断联、换层或关闭开关时清队列。
- 分帧预算用于延后处理，不用于丢弃已接纳任务；生产速度持续超过消费速度时可能增加确认延迟。

### 激进单位/身体上报

- 在原生可靠攻击消息尾部附加24字节版本化二进制记录，上报客机伤害、结构伤害与力量。
- 不再另发一份独立单位伤害消息，不走 JSON/GZip/Base64；主机在同一次原攻击处理中校验并结算一次，避免延迟第二次扣血。
- 保留原目标、距离、阵营、频率、护甲及附加伤害流程。非法、不可信或缺失上报时回退基础重算。
- 覆盖 `DamageBuilding` 与 `DoPVPMeleeDamage` 对应分支；其他动物独立 BoxCast 等攻击路径仍由原 MP 处理，不宣称全部敌人的全部攻击已覆盖。
- 这不是禁用回血；真实回血保留。两端须更新相同修订，不能仅凭版本号同为1.5.0判断二进制相同。

## 2. 客机离场后的遗留物品清理

主要文件：`GhostItemRelay.cs`、`NetworkObjectIndex.cs`（位于 `src/DDEN.MPfix/`）。

- 主机在 `DetachSyncKeepMesh` 前捕获实体 ID、Version、资源 ID 与准确对象，解绑成功且进入 `SAVESTATE_` 后才形成权威记录。
- 通知与核验使用 `ddn.mp.ghostitems.v2`、`ddn.mp.ghostitems.verify.v2`。CUCoreLib 广播可被客机转发，因此广播本身不授权删除，必须由主机核验。
- 客机维护对象绑定索引，拒绝本地私有 ID、旧代次与旧绑定；不再按同类物品+坐标猜测，不做全场物品搜索。
- 每帧最多清理8件，达到1ms预算暂停；叶子优先。持有中的物品、含未确认内容物的容器保留。
- 使用原生内部实体退出流程，避免远端客机的公开 `Destroy()` 无效后又重建网格；特殊退出期间避免重放旧状态及额外销毁效果。
- 快速重连、对象重绑、换层、断联或关闭开关会取消失效任务。
- **不删除主机保存的真实背包，不凭通知清理正常掉落。** 未启用离线背包存档、未进入主机确认的保存路径时，不因某玩家退出而擅自删除其物品。

此修改修正了旧清理路线的身份匹配与执行缺陷；尚不能据此断言用户报告的全部掉帧都来自这一路径。

## 4. 性能跟踪器改造

源码目录：`src/DDEN.NetPerfTracker/`。仍为只读、零 Harmony 补丁模块。

### 指标含义纠正

- 物理步/帧仅表示 `FixedUpdate` 调度次数与渲染帧数之比，不再当作物理耗时或压力。
- 同样50Hz物理调度，60fps约为0.83步/帧，约13.44fps可达3.72步/帧；该变化本身不能证明物理计算变重。
- 物品/刚体区分注册、启用、无父级动态、清醒、休眠和向下运动；不再将休眠的动态刚体统称为活跃计算。
- 数量翻倍可能涉及旧对象被启用或唤醒，不能单凭数量确认复制；向下运动或无碰撞也不是单独的故障证据。
- 对象清点显示完成时间、数据年龄和统计跨度，不伪装成同一时刻的快照。

### 采样与绘图开销

- `ItemCensus` 复用 `Item.allItems` 引用数组；默认15秒一次，玩家数变化后10秒内临时每秒清点。
- 物品每帧至多64件；可选场景树遍历每帧至多128次操作，两者共享默认0.4ms预算。原生调用不能抢占，慢分片记录真实成本并退避。
- 额外场景统计、碰撞检查默认关闭；对象清点与计时源探测只在页面曾打开后启动。
- 环形历史、复用组件列表与缓存纹理替代重复搬移历史、整场搜索和逐像素 GUI 绘制；四图2×2排列，保留尖峰，暂停区间留空。

### CPU/GPU与等待计时

- `PhysicsTiming` 仅接受准确的 `Physics2D.Simulate` 纳秒计时源，缺失显示不可用，不从补步数推算。
- `FrameStages` 按需读取CPU整帧、CPU主线程、渲染线程、GPU、呈现等待、主动限帧等待与主循环7个准确计时器。
- 阶段计时默认关闭，预热8次读取；缺失不填零，窗口失焦时不评估渲染/GPU。
- 阶段计时可能延迟数帧，不能相加；整帧与主循环包含等待，呈现等待不能直接当成GPU算力不足。
- 仅提供可用阶段线索，不提供具体函数调用栈。采样自身有成本，不承诺零掉帧。

### 明显标记与突变记录

- 红色：低于FPS警戒或明显长帧的事实；橙色：开销偏高/排查线索；蓝色：状态变化及正常限帧等待；灰色：关闭、预热、失焦未评估或缺失。
- 标记同时提供文字，参考帧率与突变阈值可调，不改变游戏自己的限帧设置。
- `PerfAlerts` 逐帧观察耗时，建立平滑基线后同时检查变化倍数与最小增量；数量比较基于两次完整清点，不因1变2就报警。
- 最近160条事件保存在内存，界面可回看；保留首次/末次时间、前后值、阈值、说明、峰值及重复次数。默认3秒内同指标重复事件合并，低帧事件保存最低FPS。
- 世界/连接变化、恢复采样或修改设置时重建基线；历史事件保留。
- 对象事件记录清点结束时间和前次清点时间；阶段事件标明读取时间与延迟限制，不虚构精确故障瞬间。

### 日志

- 仅手动点击导出时写入 `BepInEx/config/DDEN/perf-*.log`，不恢复实时逐条写盘；旧 `WriteLog` 键仅保留兼容。
- 格式升级为 `schema=3`；每点保存当时的设置、焦点、阈值、计时与清点成本，不用导出时的当前值覆盖历史。
- `PerfLog` 将性能点和 `EVENT` 按时间合并；较晚才发现的旧清点结果仍放在对应时间，采样间隔内的短暂事件不会因尚无定时采样点而被丢弃。
- `ValidReads` 是有效读取次数，不保证是不同原生帧。
