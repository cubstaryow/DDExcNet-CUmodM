## DDEN 是什么

《Casualties Unknown》的模组套件，给游戏加一个统一的管理界面，并把联机（Together / CasualtiesMP）里那些
「看着不对劲但又不是崩溃」的毛病逐条修掉：客机买了东西变两份、挖掉的方块又长回来、穿上装备主机看不见、
物品穿墙掉下去、商人扣钱不发货、一台客机掉线后另一台卡成幻灯片……

装好之后按 **F11** 打开界面（如果 F11 被别的模组占了会自动换一个键，并在界面里告诉你）。

## 模块说明

| 模块 | 作用 | 必需 |
| --- | --- | --- |
| **管理界面**（`DDExcNet-CUmodM.dll`） | 所有功能的开关与说明都在这一个窗口里：总览、兼容性检查、全部配置、每个模块自己的页面、关于页。也可以自动识别**别人做的模组**，把它们的设置也列进来一起改。 | 是 |
| **多人修复**（`DDEN.MPfix.dll`） | 联机毛病的主修集合，详见下表。单人玩也开着没坏处。 | 是（联机） |
| **存档编辑器**（`DDEN.SaveEditor.dll`） | 在界面里直接看/改存档：角色数值、物品、进度；支持 QoL 的多存档位。改错了会自动留备份。 | 否（不想改存档的可以删掉这个文件） |
| **性能跟踪器**（`DDEN.NetPerfTracker.dll`） | 单独一页「性能分析」：帧数、CPU、物理压力、世界里的物品/角色数量都画成曲线，可以鼠标悬停读数，并把数据写进日志文件。**它只是观察，不改游戏任何东西**。遇到掉帧时开着它，把日志发给作者就能定位。 | 否（不影响游戏） |
| **公共层**（`DDEN.Shared.dll`） | 上面几个模块共用的基础部分，玩家不用管，也不要删。 | 是 |

## 多人修复都修了什么（玩家视角）

一条现象对应一处修复，不重复：

| 你遇到的情况 | 现在的表现 |
| --- | --- |
| 联机时「无芯片模式」两边不一样：主机开了，自己这边 HUD 变了但名牌/语音没变 | 一律以主机为准，本机自动跟随（默认每 30 秒核对一次） |
| 模组加的物品在联机里做不出来 / 造出来只有自己看得见 | 主机负责真正生成并登记，其他人也看得到 |
| 客机在商人那儿买完，背包里变两份 | 一件。客机不再自己额外造一份 |
| 客机穿上的装备，主机看还是空手；或者物品跟着人到处跑 | 两边显示一致，穿上就是穿上 |
| 丢在地上的物品穿过墙和地板往下消失 | 掉在脚下，能正常捡回来 |
| 拿在手上/穿在身上的物品浮在旁边、位置不对 | 会贴回原位（只修正位置，不动朝向和大小） |
| 换下装备后，身上的贴图还挂着 | 残留贴图会自己清掉 |
| 物品能打开，但既不算穿戴也不在背包（卡在角色身上） | 自动归位到背包；放不进就落到地上（不会删） |
| 客机挖掉的方块，一会儿又长回来 | 挖掉就是挖掉，两边破坏进度一致 |
| 挖方块时血量先掉一截、又弹回去一部分 | 不再跳。世界里的伤害倍率两边算法对齐了 |
| 打开商人时商品表两边不一致，付了钱不发货 | 打开交易界面时会重新对齐一次商品表 |
| 一台客机掉线后，另一台客机帧数暴跌、卡成幻灯片 | 掉线遗留的异常物品会被原地停下，不再一直拖着物理算（实测能从十几帧救回正常） |

## 娱乐开关（默认关闭）

- **「道生一 一生二」**：联机时在商人那儿买东西会多送一件（满弹匣）。想玩自己在界面里打开，默认关着。

## 已知限制

- **挖方块的"信任上限"**：客机上报的破坏量如果超过主机账上数值的若干倍会被拒绝（默认 6 倍）。
  这是故意的，防止一镐敲穿钢墙。觉得工具太强被卡就把这个倍数调大。
- **掉线后的帧数问题**是缓解，不是根治：残留物会被停下，但彻底清理要等换层或重连
  （这是联机框架自身的清理时机，模组不去动它）。
- 性能跟踪器本身也会占一点点性能（每 5 秒统计一次世界对象，耗时写在日志里，太贵时会自动降级）。

## 出问题了怎么反馈

1. 打开 `BepInEx/LogOutput.log`，把**出现问题时那一段**发出来；
2. 如果是掉帧/卡顿，再附上性能分析页里点「打开日志目录」得到的那份日志（`BepInEx/config/DDEN/perf-*.log`）；
3. 说明当时是单人还是联机、你是主机还是客机、几个客机。
