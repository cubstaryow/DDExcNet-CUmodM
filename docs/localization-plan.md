# 中文／English双语模式方案

**状态：仅方案，v1.6.0本次未实现语言选择或界面英译。** 用户本轮选择先整理现有文档。以下名称／接口都是建议，不能当作已存在的API。

## 目标与选择入口

建议管理器总览或界面设置中提供清晰的 `语言 / Language` 选项：`简体中文`、`English`。默认中文，保持现有用户习惯；切换后立即重绘，保存在本机，下次启动沿用。不在本轮扩展自动跟随游戏语言等其它模式。

覆盖管理器导航、按钮、状态、配置标签与说明、五项提示、依赖／版本提示、编辑器固定文案和性能诊断解释。物品／液体等游戏内容名称继续使用游戏及其模组的本地化，不能通过翻译UI改变游戏语言。

## 结构建议

1. 在Shared加入轻量文本目录，使用稳定的文本ID与中文／英文资源表。代码传递ID和参数；例子 `mp.unchipped.problem`对应“主机开无芯片，客机仍有芯片”。加载一次并缓存，GUI内不逐次读取文件或扫描程序集。
2. 提供“取文本、带参数格式化、语言变化通知”能力。切换时只清文本／尺寸相关缓存，重新计算滚动高度、列宽与工具提示；不重新安装补丁、不重连、不触发存档写入。
3. 配置显示层映射原始Section／Key到文本ID，DdenDocs也用同一目录。BepInEx cfg的原键保持不变；英文模式只改变可见标题和说明，原配置文件不自动翻译或迁移。
4. 英文长句使用测宽、换行或提示框，不能只依赖中文固定宽度。已绘制图表的说明与事件记录应保存稳定事件ID／参数，再按当前语言显示，避免切换前后的记录混在两种语言中。
5. 缺英文译文回退中文，并在开发检查中报告缺失；参数不匹配时安全回退，不抛到Unity。文案ID仅用于内部，不显示给玩家。

## 身份与多人边界

- 语言是**本机界面偏好**，不进入MPfix的主机权威白名单，不由主机覆盖；客机采用主机修复配置后仍可选择自己的语言。
- 不改cfg键、插件GUID、存档字段、物品ID、SteamID、频道、报告格式或伤害逻辑。搜索同时可接受游戏当前名称、另一语言目录名称（已有时）与稳定ID。
- 不翻译玩家名字、玩家输入、原始JSON键、物品自定义名与上游日志。技术日志保留稳定事件码／字段，必要时另外输出选择语言的说明。
- 无芯片的规则说明与伤害基础／激进说明在两份语言表中须有对应词汇，避免英文又写成“cosmetic only”或“guaranteed recalculation”。

## 外部模组与独立模式

L1零引用约定继续可用，旧模组只交ConfigEntry时原样显示其说明，不承诺自动翻译第三方内容。后续可另行约定可选的显示文本提供者，必须标版本、可回退，不让旧扫描器或旧外部模组失效。

ET-HeatingCageFix不能因双语而增加Shared硬依赖。可选方案是在独立模组保留自己的小文本目录和语言配置，管理器有能力时通过可选反射传递“当前显示语言”，无管理器时仍按本机设置运行；需先明确谁管理临时显示偏好，不能把运行配置一并覆盖。此扩展尚未实现。

## 分步落地与验收

先实现语言目录、管理器选择与布局刷新，再接MPfix和配置提示，最后编辑器、性能解释与外部可选约定。文档可另建英文玩家README并互链，技术文档是否全译由后续范围决定；本轮不建立占位英文文档冒充已翻译。

验收至少包括：两语言随时切换／重启持久化；不同DPI与窄窗口不溢出且滚动触底；旧cfg无需迁移；主客机不同语言联机正常且主机模式不锁语言；游戏中英文物品名与用户文本不被改写；缺译文／参数失配可回退；没有管理器时独立模组仍加载；切换不发伤害消息、不改存档、无持续逐帧文本解析开销。
