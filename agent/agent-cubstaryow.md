# cubstaryow 协作者维护说明

本文件属于cubstaryow协作者使用的agent维护说明。公共协作入口见 [根目录agent.md](../agent.md)，其他协作者使用自己的说明，不将本文件自动视为所有人的个人工作约定。文中未作链接的源码路径以仓库根目录为基准。

先读 [玩家入口](../README.md)、[文档索引](../docs/README.md)、[当前功能](../docs/features.md) 与 [构建检查](../docs/development.md)。描述与代码冲突时先核对源码，记录证据，不沿用历史结论。

## 角色分工（2026-11-22 用户定）

cubstaryow 名下有两位 agent 在同一个仓库工作，分工如下（同一身份，不同执行者）：

| 执行者 | 只做什么 | 不做什么 |
| --- | --- | --- |
| **DeepSeek（cubstaryow）** | 上传（`git push` / Release 附件）、打包（`scripts/release.ps1`、产物与校验、发布说明成稿）、文案编辑（README / docs / 发布说明 / 变更记录）、工作目录整理（构建产物、过时反编译与废弃工具，不含删源码） | 代码修改与功能实现（用户当次明确允许时才可动代码） |
| **ChatGPT（cubstaryow）** | **代码修改与功能修复**、必要编译测试及**文档校对** | 默认不做上传、打包与文案编辑；当次用户明确指定的任务按当次授权执行 |

要点：

1. 一位执行者不要替另一位改其负责范围内的产物：DeepSeek 不擅自改代码逻辑，ChatGPT 的代码改动由 DeepSeek 负责打包与文案同步是允许的。
2. 两边的改动都以 **用户当次指令** 为准；本文件是默认分工，不是禁止事项清单。
3. 交接时在 `CHANGE.md` 记录改了什么、验证到什么程度，另一方可据此打包或校对。
4. 无论哪一方：不动游戏进程、不碰他人模组文件、不 force push、不擅自改 remote 或合并 master。

请求归属速查：

| 请求 | 归属 |
| --- | --- |
| 修 bug / 加开关 / 改逻辑 / 功能实现 | **ChatGPT**（DeepSeek 仅在用户点名时参与） |
| 打包 / 出 1.x 发布包 / 同步发布说明 | DeepSeek／其他负责发布的agent |
| 改 README / 文档整理 / 措辞统一 | DeepSeek |
| 文档校对（对照代码检查文档是否准确） | **ChatGPT** |
| 清理目录 / 删过时反编译与工具 | DeepSeek |
| git push / 上传 Release | DeepSeek／其他负责上传的agent；本次文档校对后的push已获用户明确授权 |

## 目录约定

- 项目根目录：L:\github\game\CUmod。
- decomp为只读反编译参考，docs为文档，agent为多agent协作说明；我们使用agent/agent-cubstaryow.md。
- 最终编译交付统一放dist/<版本>/；bin/obj仅为编译中间产物，不作为最终交付位置。打包、上传和文案默认由其他agent负责。

## 工作边界

- DDEN组件独立版本：Shared 2.0.1（API v1）、管理器2.1.0、MPfix 1.8.0、性能跟踪器2.3.1、增强0.2.1-alpha、存档编辑器2.0.1-alpha、UnitListMgr 0.1.2-alpha、LoongNova 1.0.1；各csproj独立维护，不再统一升号，见[版本契约](../docs/component-versions.md)。DDExcNet发布包仅六个DDEN产物（含Shared）；ET-Fix／JDI-DDEN独立版本，不随包发布，不把Unity引擎版本当游戏版本。
- Git操作以用户授权及仓库工作流程为准；在 `dev`提交经过检查的相关文件，获准后普通推送 `origin/dev`。不force push、不改remote、不替用户合并master、打tag或创建Release。不要把一次任务的授权推广到无关任务。
- 写入L盘需依照工具权限申请执行；不要把工具权限失败误判为仓库bare或擅自修改git配置。保护用户已有改动，不用reset/clean丢弃内容，不用无差别add把无关文件带入提交。
- 不提交 `bin/obj/dist/artifacts/decomp/backup`或商业游戏／第三方依赖。反编译仅阅读结论，不复制他人实现。
- **发布包只含 DDEN 六个组件**（公共层 / 管理器 / 多人修复 / 性能跟踪器 / 存档编辑器 / 物品工具）；独立外部模组「ET-Fix（ET 加热笼修复）」不随包发布，本机部署仍会带上它供联调，但不进 dist。
- **外部模组冻结（2026-11-22 用户定）**：`src/外部mod/` 下的 ET-Fix、JDI-DDEN 版本号、代码、文档一律不主动变更；只有用户当次明确点名某个外部模组时才动，且不动另一个。DDEN 及其子模块的版本号自身独立维护。
- **不跑 UITEST（2026-11-22 用户定）**：不默认启动游戏做 UITEST / SELFTEST 冒烟；只做编译与离线检查，用户明确要求验证界面时才启动，跑完确认 `BepInEx/config/cumod.uitest` 已删除。
- 不停止用户游戏。部署前确认已退出；只处理列明的自有文件，不创建插件备份，不碰其他模组，不通配删除plugins目录。不在未授权时改真实存档／配置。
- 源码及脚本MPL-2.0，资源／名称／世界观按LICENSE-ASSETS；保留归属。世界观文案放资源文件，不放源码字符串。

## 目录与契约

`src/AGENTS.md`规定DDEN模块约束；独立外部模组在 `src/外部mod/<名称>/`，ET修复读 [专属AGENTS](../src/外部mod/ET-Fix/AGENTS.md)。DDEN内部模块通过Shared `IDdenModule/DdenHub`接入，外部L1通过public static桥，不强制引用公共层。

管理器入口必须先识别 `config:`、`ext:`、`extconfig:`再找内部模块。外部“配置”始终显示配置项，自定义功能页另有入口。列表高度按实际内容计算，滚动成对结束并在异常时清理。

## 描述必须准确

1. 无芯片核心问题是“主机开无芯片，客机仍有芯片”；同步实际规则与本地玩家，不是仅改HUD／名牌。30秒watchdog核对缓存值；客机另有20秒主动请求。
2. 伤害修复只补主机漏乘的世界伤害倍率（方块/单位/角色肢体三条分支）。主机重跑使用攻击客机的远端角色状态，不使用主机自己的种族／力量，不保证状态副本相同。
3. **激进上报与穿戴兜底已于 v1.7.1 后剔除**（备份 `decomp/backup-aggressive-wear/`），不要再加回来或写成现有能力；不能写“所有敌人／所有伤害已修好”。
4. 区分构建、离线模拟、菜单绘制与真实多人验收。未测项明确写出，不承诺零开销或必定恢复。
5. README与界面面向玩家；技术细节进入docs。旧结论归入history并标过时，不与当前手册并列；当前状态见CHANGE与description-audit。

## 实现不变量

- 无芯片：主机真值来自 `Mp.HostUnchipped`；客机一起更新world、RunUnchippedLock与本地ScavPlayer。
- 伤害：`BlockDamageRelax`仅补hostOwnDamage后交回原判定；不要恢复已删除的BlockDamageRatio或工具耐久同步。单位AttackInfo复制后改字段，不把世界倍率乘到击退。
- 合成：CCL正常结果优先；作用域内主机结果为空才兜底一次，不抢前缀生成、不克隆现存物品。娱乐赠品独立。
- 穿戴兜底已剔除（见上）；物理保险只管实际丢弃，不全场扫描、不挪位置。
- 离场卡顿：**已剔除，不再尝试**（该广播清理方案实测无效，v1.7.1不再尝试此项修复）。`GhostItemRelay` 与 `RelayGhostItems` 已从 MPfix 移除，源码备份在 `decomp/backup-ghostitems/`；不要用按坐标猜副本、冻结/抬升/全场搜索等旧思路重做。
- Together：当前核对5.5.5；客机FixInvSync重试补丁已按用户要求移除，不再恢复。
- 面板：只经管理器打开，默认F11，冲突向F10～F1查找，F12留给Steam；物品轮盘快捷键保留。
- 名称：只改显示，不改SteamID／逻辑名／存档身份；只用游戏字库，缺字 `?`，不加系统字体兜底。
- 主机权威配置：临时生效层，不覆盖本机cfg；仅主客机均采用才锁客机，退出恢复。缺依赖限制本机和主机临时值。
- 编辑器：只改用户字段，未知节点原样保留；items/itemComponents成对处理；保存检查外部修改及QoL忙，原子写＋备份。cheatedSave仅显式修改，不能宣称保证平台成就。
- 性能：基础跟踪器零Harmony补丁；用户于2026-11-24明确要求的独立增强模块可安装纯计时Harmony钩子，默认关闭，不改逻辑／参数／异常／网络；步／帧只反映调度，准确计时缺失显示不可用；详细统计默认关，手动导出日志，等待／数量是线索而非根因证明。

详细原理、构建命令和验收清单分别在features、development、各工具中，不在本文件重复存旧文档。管理器、MPfix与性能跟踪器已实现双语，后续范围见 [localization-plan](../docs/localization-plan.md)。

## 物品与工具描述规范（2026-11-25 用户定）

- 玩家物品描述保持简洁：先写装备位置／工具类别，再写核心用途、容量、专用耗材限制及必要的伤害、速度、消耗。示例：腰部装备，可飞行，提供缓降，提供6u的工具挂载。仅接受实验性龙息单元。缓降：每秒消耗0.5单位能源；飞行：每秒消耗8单位能源。
- 不在描述堆叠存档、网络认证、实现原理、测试状态与重复操作解释；技术细节进入维护文档，操作放独立提示。保留现有简洁描述的语气，不为统一格式改写无关物品。
- 安装提示简短、随实际状态更新：空槽“可安装电池：实验性龙息单元”，已装“龙息单元就绪：1000/1000（100%）”（数值动态变化）。物品名称与说明只改显示，不改ID、存档键、配方身份及网络字段。
- 基础伤害与间隔明确是基础值；最终伤害及挥速仍受原版角色、世界规则等影响。文案与实际代码同步更新，不保留过时消耗或容量。
