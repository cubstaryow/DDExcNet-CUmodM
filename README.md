# DDEN · CUmod

《Casualties Unknown》的模组合集：一个统一的管理器，加上一套专治**联机不同步**的修复。

> 作者：**cubstaryow**
> 本版（1.6.0）对得上《Casualties Unknown》2022.3 版游戏，以及联机框架 Together / CasualtiesMP **5.5.4**（5.5.3 也核对过）。

## 它修好了什么

装完之后，下面这些联机常见毛病会消失或明显缓解：

| 你会遇到的毛病 | 现在的表现 |
| --- | --- |
| 主机改了「无芯片」设置，客机界面变了但名牌、附近语音还是旧的 | 以主机为准，客机自动跟上；万一被改动，会自己核对回来 |
| 联机合成模组加的物品时提示无法生成物品 | 仅在生成失败时尝试补救，正常生成时不额外给一份 |
| 中文名字变成问号、数字，或者主机名字为空 | 「玩家名称」分组可开启尝试修复，只改变本机显示，效果仍需多人实测 |
| 客机明明穿上了装备，主机眼里它还在地上、甚至跟着人跑 | 主机认出那件装备并穿对位置，两边看到的一致 |
| 丢出去的东西穿墙、掉进地图外面 | 丢出的物品会正常落地 |
| 客机挖掉方块又长回来，挖的时候方块血量还忽上忽下 | 两边血量与破坏结果一致；方块按正常流程碎掉，掉落照旧 |
| 客机付钱买了商人的东西却没拿到 | 每次打开商人界面都会重新对齐商品表 |
| 一台客机掉线后，另一台客机卡成幻灯片 | 按主机确认的准确清单清理遗留副本，减少持续掉帧；主机与客机都需更新本次包 |
| （娱乐）想买一件拿两件 | 「道生一 一生二」开关，默认关闭 |

每一项的**具体原因和我们怎么修的**写在 [docs/features.md](docs/features.md)，
这里只列你会感受到的结果。

## 装了之后你会看到什么

按快捷键打开管理器（默认 **F8**；如果和别的模组撞键，会自己换一个空闲键并记到设置里）：

- **总览**：每个模组一张卡片，显示它是正常工作还是功能受限。
- **兼容性**：装了什么模组、有没有互相抢快捷键、有没有旧版本残留文件。
- **全部配置**：所有模组的设置集中在一页，按模组和分组排列，改完立刻生效。
- **存档编辑器**：按物品、角色、世界设置分区；可编辑弹匣容量、子弹数、弹膛状态、电池与电量，以及容器内的多种液体和各自数量。名称跟随游戏语言，支持中文搜索；物品图标等比居中。修改先在工作区暂存，查看清单后保存。窄窗口可切换总览与详情。
- **其它模组的设置**：没做适配的模组，只要它肯把设置交出来，也能在这里统一改。
- **CageFix（可选）**：尝试修复 Enhanced Tools 加热笼关闭后仍腐坏、仍能充当合成热源的问题；支持记住开关及向主机确认状态，仍需游戏内实测。它可独立安装，使用 DDEN 时配置会出现在“其它模组的设置”。
- **关于 DDExcNet**：世界观出处、作者、各个组件的版本。
- **性能分析**：把帧耗时、物理模拟计时和清醒／休眠物品分开看，也会显示跟踪器自身耗时。可按需开启 CPU／GPU 阶段计时；低帧和可疑开销有明显标记，突变记录保留时间、前后值和解释。详细统计默认关闭，点「导出日志」才保存文件。

设置也可以直接改游戏目录下的 `BepInEx/config/com.dden.cumodm.cfg`、`com.dden.mpfix.cfg`。
控制台也能输入 `dden` 打开管理器。

多人修复的总开关下新增「采用权威主机配置」，默认关闭。主机启用后按需下发设置，客机也启用才临时采用，配置区会显示「（主机权威模式）」。主机仍可编辑；采用中的客机仅保留总开关和采用选项可编辑，退出联机或取消采用后恢复本机设置，不覆盖本机配置文件。

缺少某项功能需要的前置模组时，对应功能会关闭，开关置灰并显示原因。采用主机配置也不能绕过这个限制；补齐前置并重新启动后，可以自行重新开启。

多人名称显示修复只使用游戏现有字体，缺少的字显示为 `?`，不使用系统字体兜底。

## 安装

1. 游戏先装好 **BepInEx 5**（游戏目录下会出现 `BepInEx/` 文件夹）。
2. 把包里的文件**一起**放进 `BepInEx/plugins/DDEN/` —— 它们必须放在同一个文件夹里，别拆开。
3. 想用联机相关的修复，还需要装联机框架 **CUCoreLib** 与 **Together / CasualtiesMP**。
   没装也能进游戏，只是联机那部分修复不会生效，管理器里会标成「功能受限」。

> 本地完整包包含存档编辑器，它仍是可选组件，不使用时可以不安装。

CageFix 需要 Enhanced Tools 和 CUCoreLib，可单独安装，不要求安装 DDEN。没有管理器时，可以关游戏后编辑其配置文件；多人建议各端安装相同版本。缺少所需模组时对应功能关闭，并在管理器里显示原因。独立说明见 [CageFix](src/外部mod/CageFix/README.md)。

总览支持滚动；外部模组的“配置”直接打开独立设置页，有自定义功能页的另有“打开界面”入口。

## 设置建议

方块、箱子/植物/动物、角色/肢体类敌人的近战伤害，各有独立的修复开关。

- 平时先使用默认的伤害重算，主机和客机都安装同一版本。
- 如果仍有伤害回弹，可打开激进模式。它只处理已经开启修复的分支；对应分支关闭后，激进模式也不会处理它。
- 激进模式会分批处理大量碎块，尽量分散开销；多人高速挖掘仍可能影响帧数或增加确认等待时间，需要实际联机验证。

## 构建

需要 .NET SDK 10。仓库里只有一处本机路径要改：`Directory.Build.props` 里的游戏目录
（或用 `-p:GameDir=...` 传进去）。

```bash
dotnet build CUmod.slnx -v m     # 只编译
./scripts/build.sh               # 编译并部署到游戏的 plugins/DDEN
```

部署前**请先关游戏**，否则文件被占用会复制失败。构建与部署的细节、以及每个修复的坑，
都写在 [AGENTS.md](AGENTS.md) 里。

## 已知限制

- 联机部分的修复是针对上面写的联机框架版本逐点核对做的；框架大版本一换可能对不上，
  管理器会在日志里提示版本不符。
- 存档编辑器只改你点过的字段，**不会**自动动「禁用成就」标记，需要你自己在「进度与成就」页切。保存前会核对文件是否被游戏更新，保存失败时保留原文件；自定义中文名称也会保留。
- 反编译参考和构建产物都不会进仓库。

## 关于 DDExcNet

DDExcNet 是「幼龙云」所属「视界」世界观下的**龙域信息交换网络标准** —— 一套约定
「不同端口、不同实现之间怎么互相认出对方、怎么交换状态」的接口规范。
本仓库是它在《Casualties Unknown》里的落地实现：一个管理器、一套联机修复、一个可选的存档编辑器。
